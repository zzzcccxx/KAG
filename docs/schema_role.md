# SCHEMA 作用说明

在 KAG / OpenSPG 体系中，`SCHEMA` 是领域知识建模的核心约束层，决定“可以抽取什么”“如何存储”“如何推理与检索”。

## 1. SCHEMA 是什么

SCHEMA 用于定义知识图谱中的：

- 类型（Type）：如 `Company`、`Person`、`Disease`
- 属性（Property）：如 `name`、`founded_at`、`symptom`
- 关系（Relation）：如 `Person_workFor_Company`
- 约束（Constraint）：如非空、枚举、正则、多值

它相当于知识库的“数据结构 + 业务规则”。

## 2. SCHEMA 的核心价值

### 2.1 提升抽取质量

构建阶段，SCHEMA 能约束 LLM/抽取器只生成合法结构，减少脏数据和字段漂移。

### 2.2 统一团队语义

通过显式定义类型与字段语义，不同开发者与业务专家可以基于同一标准协作。

### 2.3 强化检索与推理

高质量的类型和关系定义可以显著提升：

- 图检索命中率
- 多跳推理可解释性
- 结果可追溯性

### 2.4 降低后续维护成本

前期设计好 SCHEMA，可以减少后续数据迁移、字段兼容和规则回填的成本。

## 3. 什么时候需要调整 SCHEMA

当出现以下情况时，建议更新 SCHEMA：

1. 业务新增核心对象（新实体类型）
2. 问答场景需要新属性或新关系
3. 现有字段定义不准确（例如类型、约束不合理）
4. 推理链路缺少关键连接边

## 4. 调整 SCHEMA 的最佳实践

1. **小步迭代**：一次只改一个主题域。
2. **先建模再抽数**：先确定类型/关系，再批量构建。
3. **先严后松**：先用严格约束保证质量，再按需放宽。
4. **版本管理**：每次变更都记录版本与迁移说明。
5. **样本回归**：用典型问答做回归测试，验证变更收益。

## 5. 与“SCHEMA 调整助手”配合使用

你可以先在 [SCHEMA 调整助手](./schema_editor) 中快速编辑类型与属性，再复制生成片段到业务 schema 文件中进行验证。

这样可以把“设计—修改—验证”的周期压缩到分钟级，提升领域知识库迭代效率。
